# 截屏工具桌面程序调试与发布流程

## 1. 目标

本项目目标是生成类似电脑管家的 Windows 桌面应用，提供：

- 任务列表、任务进度、结果报告和设置页面。
- 内嵌浏览器执行区域。
- 浏览器可视化执行和隐藏后台执行两种模式。
- 企业名单导入、网站查询、截图保存和 Excel 汇总报告。

日常开发不应依赖下载安装包。源码开发、解包版验证和安装包验收使用不同流程。

## 2. 三种运行方式

### 2.1 开发模式

用于日常开发和界面调试。

- 直接运行项目源码。
- UI 支持热更新，修改后自动刷新。
- 开启开发者工具，查看页面、日志、网络请求和任务状态。
- 不生成安装包，不写入系统安装目录。
- 使用模拟任务、模拟网站和测试企业数据，避免每次调试都访问真实网站。

示例命令：

```bash
npm run dev
```

### 2.2 Windows 解包版

用于验证桌面窗口、托盘、内嵌浏览器、隐藏模式和本地文件读写。

- 构建一次后生成 Windows 解包目录，例如 `win-unpacked`。
- 直接运行目录中的 `.exe`，无需安装。
- 适合验证真实桌面行为和本地权限。
- 调试期间不需要反复下载或安装。

示例命令：

```bash
npm run build
```

然后直接运行构建产物目录中的应用程序。

### 2.3 安装包

用于版本发布和安装流程验收，不作为日常开发入口。

重点验证：

- 首次安装和升级。
- 文件权限和默认保存目录。
- 开机启动和托盘行为（如启用）。
- 自动更新（如启用）。
- 卸载后数据保留规则。
- 不同 Windows 环境下的启动和运行。

示例命令：

```bash
npm run package
```

## 3. 推荐工作流

```text
源码开发 + 热更新
        ↓
本地模拟数据验证
        ↓
Windows 解包版验证
        ↓
真实网站集成测试
        ↓
安装包验收
        ↓
正式发布
```

原则：日常调试运行源码，阶段性验证运行解包版，发布前才测试安装包。

## 4. 应用架构建议

将应用拆分为桌面界面、浏览器执行和任务执行服务三层：

```text
桌面应用界面
├─ 任务列表、进度、结果、设置
├─ 内嵌浏览器预览区
└─ 任务执行服务
   ├─ 企业名单处理
   ├─ 网站查询适配
   ├─ 截图保存
   └─ Excel 报告生成
```

这样可以分别调试 UI、浏览器显示/隐藏、自动化流程和报告生成，不必每次都跑完整任务。

## 5. 调试数据策略

### 5.1 UI 调试

使用固定的模拟任务数据，覆盖以下状态：

- 待开始。
- 执行中。
- 已暂停。
- 等待人工处理。
- 成功。
- 无记录。
- 失败。
- 部分完成。
- 已终止。

### 5.2 浏览器预览调试

使用本地模拟网页，不依赖真实目标网站。模拟网页应覆盖：

- 正常查询结果。
- 无查询结果。
- 页面加载超时。
- 页面结构变化。
- 需要人工处理的验证码或登录拦截页面。
- 超过一屏的长页面。

### 5.3 报告调试

使用固定企业名单和固定核查项，验证：

- 截图目录是否正确生成。
- 文件名是否包含企业、网站/核查项和执行时间。
- Excel 是否包含全部“企业 × 核查项”执行项。
- 报告状态与截图文件数量是否一致。
- 失败项是否能单独重试。

### 5.4 真实网站集成测试

真实网站只在集成测试阶段使用。测试时应控制企业数量、请求频率和并发数量，并遵守目标网站的访问规则。遇到验证码或登录拦截时，进入“自动检测 + 人工处理 + 继续执行”流程。

## 6. 技术选型建议

### 6.1 推荐：Electron + React/Vue

适合当前 MVP 的原因：


- 内嵌 Chromium，便于实现浏览器动态预览。
- 支持可视化和隐藏浏览器窗口。
- Web UI 迭代速度快，适合电脑管家式界面。
- 开发者工具、热更新和桌面调试链路成熟。
- 便于生成 Windows 解包版和安装包。

代价是安装包较大、资源占用高于原生方案。

### 6.2 可选：Tauri + React/Vue

适合对安装包大小和资源占用要求较高的版本，但依赖 WebView2，桌面能力和调试环境需要更多约束，建议在 MVP 验证后再评估。

### 6.3 可选：WPF/WinUI + WebView2

适合长期只面向 Windows、强调原生系统体验的版本，但 UI 迭代和跨层调试成本通常高于 Electron。

## 7. 版本验收边界

### 日常开发必须可验证

- 主界面布局和导航。
- 创建任务和名单校验。
- 任务进度状态切换。
- 浏览器预览展开/隐藏。
- 暂停、继续、终止和失败重试。
- 模拟截图和 Excel 报告生成。

### 阶段性验证

- Windows 解包版启动。
- 独立浏览器实例运行。
- 隐藏模式不抢占用户焦点。
- 本地目录和文件权限。
- 应用崩溃后的任务恢复。

### 发布前验证

- 安装、升级和卸载。
- 真实目标网站适配。
- 验证码人工接管流程。
- 多显示器和 DPI 缩放。
- 任务统计、截图目录和 Excel 报告的一致性。

## 8. 后续开发约定

- 不把安装包作为日常调试入口。
- 不用真实网站替代本地模拟数据测试。
- 每新增一个任务状态，都要补充 UI、日志、恢复和报告测试。
- 每新增一个目标网站，都要补充站点适配配置、成功/无记录判断、超时和人工处理规则。
- 只有在解包版通过后，才进入安装包验收。
