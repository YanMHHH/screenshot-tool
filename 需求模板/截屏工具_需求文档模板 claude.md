## 3. 功能需求

### 3.1 核心功能

> 按优先级排列（P0/P1/P2），逐条描述功能点

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 截图触发方式 | 快捷键/按钮/API调用/定时 | P0 |
| 截图范围选择 | 全屏/区域/窗口/滚动页面 | P0 |
| 截图格式与输出 | 文件格式、存储路径、命名规则 | P0 |
| 标注/编辑能力 | 框选、文字、箭头、马赛克等 | P1 |
| 分享/上传能力 | 复制到剪贴板、上传云端、生成链接 | P1 |

## 5. 用户流程

### 5.1 主流程（Happy Path）
> 用步骤或流程图描述最典型的操作路径

```
触发截图 → 选择范围 → 预览/编辑 → 保存/分享 → 完成
```

### 5.2 异常流程

## 6. 产品形态

### 6.1 部署形式
> 桌面应用、浏览器插件、命令行工具、SDK库、还是服务端API？

> Windows / macOS / Linux / Web / 移动端？各平台优先级？

### 6.3 集成方式
> 是否需要嵌入到其他产品里？以什么形式集成（API/SDK/插件）？

### 6.4 界面形态
> 是否有GUI？极简悬浮窗、系统托盘、独立窗口？

## 7. 非功能性需求

### 7.1 性能
> 截图响应时间、大文件处理能力、内存占用上限

### 7.2 兼容性
> 操作系统版本、分辨率、DPI缩放（HiDPI）、多显示器

### 7.3 安全与隐私
> 截图数据是否落盘？是否传输？传输是否加密？日志脱敏要求？

### 7.4 可靠性
> 崩溃恢复、截图失败不丢内容等
